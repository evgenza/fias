# Миграция поискового индекса v2

`ES_INDEX` (по умолчанию `gar-addresses`) теперь означает write alias на
`<ES_INDEX>-v2`. На чистой установке индексатор создаёт индекс с закреплённым
маппингом и alias одним запросом. Bulk всегда требует alias (`require_alias`),
поэтому отсутствующий индекс не создаётся с динамическим маппингом.

Анализаторы сохраняют односимвольные номера и типы, нормализуют ё → е и не
удаляют стоп-слова. Prefix-поле использует edge_ngram 1…20; поисковый анализатор
обрезает токены до 20 символов. Основные поля сохраняют полные токены для fuzzy.

## Существующий физический индекс

Миграция выполняется отдельно от запуска сервисов, одним процессом. Остановите
все экземпляры indexer и других писателей в адресный индекс. Suggester может
продолжать читать старый индекс до переключения.

```sh
docker compose stop indexer
ES_ADDRESSES=http://127.0.0.1:9200 ES_INDEX=gar-addresses go run ./cmd/gar-search-migrate
docker compose up -d --build indexer suggester
```

Для собственного `ES_INDEX` используйте то же имя во всех сервисах и команде.
Перед миграцией сохраните snapshot Elasticsearch, если нужен откат на старый
маппинг. Команда блокирует запись в исходный индекс, создаёт v2, делает refresh
источника и синхронный reindex с refresh результата. Переключение выполняется
только при отсутствии ошибок/таймаута reindex и совпадении числа документов.
Один запрос aliases удаляет старый физический индекс и назначает его имя alias
для v2. После этого запись разрешена через alias; исходный индекс удалён.

При ошибке старый индекс остаётся доступен для чтения и заблокирован для записи.
Устраните причину и повторите команду: частично заполненный v2 используется
повторно. Если v2 имеет другой маппинг или лишние документы, команда откажет;
разберите содержимое v2 перед его пересозданием. Запуск нескольких миграций
одновременно не поддерживается. Для отказа от незавершённой миграции восстановите
запись в исходный индекс (`PUT /gar-addresses/_settings` с
`{"index.blocks.write":false}`), сохраняя прежнюю версию indexer. После успешного
переключения повторный запуск команды ничего не меняет.

Использованы [Aliases API](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/aliases.html)
и [Reindex API](https://www.elastic.co/docs/api/doc/elasticsearch/v8/operation/operation-reindex).
