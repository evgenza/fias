## Путь исполнения

`cmd/gar-importer/main.go` → `importer.ImportZIP(ctx, *ent.Client, …)` →
`garxml.DecodeXML` (потоково, per-record consume) → `ent.NewGARBatch` (сгенерирован
`ent/template/gar_batch.tmpl`) → дедупликация по ключу внутри пакета →
`CreateBulk` + `OnConflictColumns(...).Update(...)` upsert.

- `internal/model` — алиасы на Ent-типы (не независимые модели).
- `ent/schema` — единственный источник SQL-полей и XML/JSON-тегов; привязка формата —
  аннотация `GARFormat{Kind}`.
- `storage.Migrate` применяет `Schema.Create` (atlas automatic migrations);
  SQL в `migrations/` не исполняется как версионированная история.

## Каталог форматов

Сведён в [format-catalog.md](format-catalog.md): 23 Kind, root/record, ключи,
обязательные/optional-атрибуты. Перекрёстная проверка XSD ↔ `garxml` ↔ Ent:
**все 22 XSD покрывают 23 Kind** (`AS_ADDHOUSE_TYPES` использует XSD `AS_HOUSE_TYPES`),
расхождение единственное — синтетическое поле `param.source` (из имени файла, в XSD нет).
Ключи особых форматов: `AS_CHANGE_HISTORY` → `CHANGEID`, `AS_REESTR_OBJECTS` → `OBJECTID`,
`AS_OBJECT_LEVELS` → `LEVEL`. `AS_PARAM` — бизнес-ключ `(source, source_id)` и 6
нормализованных префиксов PARAM/PARAMS.

## Подтверждённые дефекты (воспроизведены на рабочем дереве)

1. **Схлопывание записей без ключа.** Запись без обязательного `ID` декодируется как
   `ID=0`; дедупликация в `gar_batch.tmpl` (`positions map[int64]`) превращает две такие
   записи в один builder. Причина — отсутствие проверки обязательных атрибутов до дедупа.
2. **Двойная семантика региона.** `archiveRegion("unexpected/AS_HOUSES_…xml") == 0` —
   файл из неизвестной папки проходит региональный фильтр как общероссийский; при этом
   `RegionCode("gar_xml/77/…")` возвращает ошибку — wrapper `gar_xml/` не поддержан.
3. **`ParseFile` принимает невозможную дату** `20269999` (проверяются только 8 цифр).
4. **`migrations/0002_param_source.sql`** добавляет `source_id bigint NOT NULL` без
   backfill: на заполненной старой `param` миграция невыполнима.
5. `--write-sql` не dry-run: подготовка плана создаёт схему, затем команда применяет миграцию.
6. Более старые входные значения могут безусловно перезаписывать новые (upsert без
   сравнения версий), нет журнала выпусков и защиты от конкурирующих импортов.
7. Upsert полного архива не удаляет остатки прежнего снимка; после сбоя остаются
   записанные пакеты, состояние неполного выпуска нигде не фиксируется.

## Текущие ограничения декодирования (закрывается этапом 1)

- Отсутствие обязательного атрибута → нулевое значение (`ID=0`, `UPDATEDATE=""` → NULL
  на NOT NULL-колонке уже в SQL, `OBJECTGUID=""`, флаги молча `false`).
- Пустое значение обязательной строки (`NAME=""`) принимается.
- GUID не проверяется на длину 36; строки не проверяются на maxLength XSD.
- Неизвестные атрибуты (новые поля будущих выпусков) молча теряются.
- Ошибка SQL-пакета не указывает на конкретную запись (диагностика — этап 4).

## Решения этапа 0

- Спецификацию обязательности/ограничений атрибутов генерировать из закреплённых XSD
  (копии кладутся в `xsd/` репозитория), а не из Ent-схем: у Ent нет minLength/maxLength,
  а задание требует сверять ограничения с XSD. Перекрёстный тест XSD ↔ Ent не даёт им
  разъехаться (единственное ожидаемое отличие — `param.source`).
- Пользовательские незакоммиченные изменения сохраняются; reset/clean не выполняются.
